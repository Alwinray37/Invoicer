# Invoicer — Invoice & Hours Tracker

A clean, minimal web app for freelancers to track work hours per job and generate PDF invoices.

---

## Tech Stack

| Layer       | Technology                          |
|-------------|-------------------------------------|
| Frontend    | React 18 + Vite                     |
| Styling     | Tailwind CSS                        |
| Routing     | React Router v6                     |
| Auth + DB   | Supabase (Postgres + Auth)          |
| PDF         | jsPDF + jspdf-autotable (in-browser)|

---

## Setup Instructions

### 1. Install dependencies

```bash
npm install
```

### 2. Set up Supabase (free)

1. Go to [supabase.com](https://supabase.com) and create a free account
2. Create a **New Project**
3. Once created, go to **Settings → API**
4. Copy your **Project URL** and **anon/public key**

### 3. Run the database schema

1. In your Supabase dashboard, go to **SQL Editor → New Query**
2. Open `src/lib/supabase.js` and copy the entire SQL block (between the `=====` comments)
3. Paste it into the SQL editor and click **Run**

This creates the tables: `jobs`, `work_items`, `invoices`, `payments`
And enables Row Level Security so users only see their own data.

### 4. Configure environment variables

```bash
cp .env.example .env
```

Edit `.env` and fill in your Supabase credentials:

```
VITE_SUPABASE_URL=https://your-project-id.supabase.co
VITE_SUPABASE_ANON_KEY=your-anon-key-here
```

### 5. Run the app

```bash
npm run dev
```

Visit `http://localhost:5173`

## Data Model

Invoicer stores four business objects in Supabase. Every object has a UUID
`id` and a `created_at` timestamp generated by the database unless noted
otherwise.

```
auth.users (Supabase Auth)
└── jobs
    ├── work_items
    └── invoices
        └── payments
```

### User

Users are managed by Supabase Auth rather than an application table. The
authenticated user's UUID is stored on each job as `user_id`. Row Level
Security (RLS) uses that relationship to ensure a user can only access their
own jobs and the work items, invoices, and payments belonging to those jobs.

### Job

A job is the top-level workspace for a client engagement. It defines the
client information and the billing rules used to calculate work-item and
invoice amounts.

| Field | Type | Description |
|---|---|---|
| `id` | UUID | Unique job identifier. |
| `user_id` | UUID | Supabase Auth user who owns the job. Required. |
| `name` | text | Job or project name. Required. |
| `client_name` | text | Client or company name. Optional. |
| `client_email` | text | Client contact email. Optional. |
| `client_address` | text | Client billing address. Optional. |
| `billing_type` | text | `hourly` or `flat`. Defaults to `hourly`. |
| `hourly_rate` | numeric(10,2) | Hourly rate, or the flat-fee price when `billing_type` is `flat`. Defaults to `0`. |
| `currency` | text | Currency code such as `USD`, `EUR`, or `GBP`. Defaults to `USD`. |
| `created_at` | timestamp | When the job was created. |

For hourly jobs, an item's amount is calculated as `hours × hourly_rate`.
Flat-fee jobs use the item's amount directly, allowing multiple separately
described items to make up one invoice.

### Work Item

A work item is one billable entry in a job's work log. It can represent hours
worked or a manually priced item for a flat-fee job.

| Field | Type | Description |
|---|---|---|
| `id` | UUID | Unique work-item identifier. |
| `job_id` | UUID | Parent job. Required; deleted with the job. |
| `description` | text | What was done. Required. |
| `date` | date | Date the work or charge applies to. Required. |
| `hours` | numeric(5,2) | Number of hours. Defaults to `0`; flat-fee items may use `0`. |
| `amount` | numeric(10,2) | Billable amount. For hourly work this is normally calculated from the job rate. |
| `invoiced` | boolean | Whether the item has been added to an invoice. Defaults to `false`. |
| `invoice_id` | UUID | Invoice containing the item; empty until invoiced. |
| `created_at` | timestamp | When the work item was created. |

Creating an invoice marks its selected work items with `invoiced: true` and
sets `invoice_id`. Voiding an invoice makes those items available for
invoicing again by resetting both values.

### Invoice

An invoice groups selected work items, records the amount owed, and provides
the information needed to generate a PDF invoice.

| Field | Type | Description |
|---|---|---|
| `id` | UUID | Unique invoice identifier. |
| `job_id` | UUID | Parent job. Required; deleted with the job. |
| `invoice_number` | text | Human-readable invoice number. Required. |
| `issued_date` | date | Date the invoice was issued. Required. |
| `due_date` | date | Payment due date. Optional. |
| `total_hours` | numeric(8,2) | Total hours from its work items; `null` for flat-fee invoices. |
| `total_amount` | numeric(10,2) | Total amount due. |
| `status` | text | `unpaid`, `partial`, `paid`, or `void`. Starts as `unpaid`. |
| `notes` | text | Additional invoice or payment-term notes. Optional. |
| `payable_to` | text | Name or business that should receive payment. |
| `payable_details` | text | Payment instructions, such as bank or account details. Optional. |
| `created_at` | timestamp | When the invoice was created. |

An invoice must contain at least one work item. Its totals are calculated
from the selected items when it is created and recalculated when an invoiced
item is edited.

### Payment

A payment records money received against an invoice. An invoice can have
multiple payments, which supports partial payments.

| Field | Type | Description |
|---|---|---|
| `id` | UUID | Unique payment identifier. |
| `invoice_id` | UUID | Invoice receiving the payment. Required; deleted with the invoice. |
| `amount` | numeric(10,2) | Payment amount. Required and greater than zero in the UI. |
| `date` | date | Date payment was received. Required. |
| `note` | text | Optional payment note or reference. |
| `created_at` | timestamp | When the payment was recorded. |

The invoice status is derived from the sum of its payments:

- `unpaid`: no payment has been recorded.
- `partial`: payments exist, but their total is less than `total_amount`.
- `paid`: payments meet or exceed `total_amount`.
- `void`: the invoice was cancelled; it cannot accept new payments.

### Relationships and security

- One user can own many jobs.
- One job can contain many work items and many invoices.
- One invoice can contain many work items and many payments.
- A work item belongs to one job and is linked to at most one invoice.
- Deleting a job cascades to its work items and invoices; deleting an invoice
  cascades to its payments.
- Supabase RLS scopes all reads and writes to the signed-in user's jobs and
  their related records.
